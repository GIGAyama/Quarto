# note 入稿の手引き（GIGAクアルト！ 紹介記事）

このフォルダに入っているもの。

```
docs/note/
├── quarto-note-article.md   記事本文。そのまま note に貼れる形
├── images/                  実際に操作して撮った画面（17点）
└── README.md                このファイル
```

## 貼るまえに直すところ

1. タイトル行の `#◯` を、正しい連載番号に置きかえてください。
   推測で埋めていません。ここだけは書き手にしか分かりません。
2. 「はじめに」に、前作との地続きを一段落足せます。
   note のアカウントに外から届かない環境で書いたため、直近の回が何だったかを
   確認できませんでした。「以前この連載で紹介した◯◯とは毛色がちがって」のような
   一文を入れると、連載の読者にとって記事の位置がはっきりします。
3. 教室で実際に使ったときの様子は、書き手が自分で足してください。
   本文には作者の実践記録を一切書いていません。書いてあるのは
   「こうなればいいと思って作った」「〜だと思います」までです。

## note に貼る手順

1. note の新規投稿を開き、タイトル欄に本文1行目の見出しを貼ります。
   本文側の `#` の行は消してください。二重に出てしまいます。
2. 本文をそのまま貼りつけます。装飾は見出しだけなので、崩れないはずです。
3. 画像は自動では入りません。`![...](images/xx.png)` の行を目印に、
   その位置で画像を手動でアップロードしてください。対応表は下にあります。
4. 画像の直後にある一行の説明は、note のキャプション欄に移してください。
   移したあと、本文からはその行を消します。
5. アプリのアドレスを書いた行は、note が自動でカード表示にします。
   前後を1行あけておくとカードになります。
6. ハッシュタグ欄の候補は、GIGAスクール、ICT教育、小学校、教材、
   プログラミング、ボードゲーム、自作アプリ、note教育、あたりです。

## 撮影のあいだに見つけて直した不具合

撮影は受け入れテストも兼ねています。今回は3つ見つかり、うち2つを直しました。
記事とは別のコミットに分けてあるので、公開の前に反映してください。

1. 勝ったときに紙吹雪が一枚も見えていなかった。
   紙吹雪を描く場所が「かち！」のポップアップより下に置かれていて、
   ポップアップと暗幕に完全に隠れていました。README と MANUAL.md は
   「紙吹雪といっしょに出ます」と書いていますが、実際には出ていませんでした。
   コミット `fix: 勝ったときの紙吹雪が見えず、CSP 違反も出ていた問題を直す`

2. 勝つたびにコンソールへ CSP 違反が出ていた。
   紙吹雪の部品が裏方の処理を作ろうとして、`worker-src 'self'` にはじかれていました。
   AUDIT.md の B1 は「CSP違反 0件」としていますが、`npm run measure` は
   ポップアップを直接開くだけで最後まで対局しないため、取りこぼしていました。
   1と同じコミットで直しています。

3. 更新のお知らせの帯が、スマートフォンで1文字ずつ縦に並んでいた。
   390px の端末では帯が 195px しか広がれず、
   「あたらしい ばん が あります」が縦一列になって画面の半分を覆っていました。
   `npm run measure` は 320 / 375 / 1366 の3幅を見ますが更新の帯は出しません。
   `npm run measure:update` は帯を出しますが 1366px でしか見ていません。
   両方のすきまに落ちていました。
   コミット `fix: 更新のお知らせの帯が、スマホで1文字ずつ縦に折り返されていた問題を直す`

どちらの修正も `npm run lint` `npm test`（10件）`npm run check`（29件と既知の逸脱1件）
`npm run measure`（60件）`npm run measure:update`（7件）が通ることを確認しています。

### 直していないこと

横持ちのときだけ、コマの見た目が重なって選びにくくなります。
左右に8個ずつ並べる配置だと、奥行き方向に潰れて見えるためです。
16個すべてが押せることは確かめましたが、いちばん狭いコマの当たり判定は
13ピクセル四方ほどしかありませんでした。縦持ちではどのコマも30ピクセル四方以上あります。
盤面を指で回せば正面に持ってこられるので、遊べなくなるほどではありません。
配置の作り替えになるため、判断を残してあります。

## 撮り直すときの手順

撮影用の道具はリポジトリに残していません。次の手順でやり直せます。

1. `npm install` と `npm i --no-save playwright` を実行します
2. `npm run build` でビルドします
3. `node <スキル>/scripts/serve.mjs dist 4180 /Quarto/` を別のターミナルで動かします
4. 撮影用のシナリオを `.tmp-shots/shots.mjs` に置きます
5. `node <スキル>/scripts/capture.mjs .tmp-shots/shots.mjs --base http://127.0.0.1:4180/Quarto/ --out docs/note/images` を実行します
6. 撮り終えたら `.tmp-shots/` を消して、`git status` に残っていないことを確かめます

3Dの盤面は文字でボタンを押せないため、シナリオ側で少し工夫が要ります。
今回は撮影のあいだだけ `src/App.jsx` に1行足して盤面の内部を外から触れるようにし、
アプリ自身の当たり判定を借りて「このコマに当たる画面上の座標」を探してから押しました。
当てずっぽうの座標で押すと、手前のコマに当たって別のものを選んでしまいます。
この1行は納品前に消してあります。差分に残っていないことは `git status` で確認済みです。

字の形については、撮影のあいだだけ Zen Maru Gothic を `dist/` に置いて配りました。
本番はこの書体を外から読みこむので、見た目を偽ってはいません。
`dist/` は `.gitignore` に入っているため、リポジトリには残っていません。

## 文体について踏襲したこと

- 太字、斜体、表、区切り記号を使っていません。見出し以外の Markdown はゼロです
- 箇条書きは手順のところだけです。それ以外は文章で書いています
- 専門用語を日常の言葉に置きかえています。
  たとえば「Service Worker のキャッシュ」は「一度開けばつながっていなくても遊べます」、
  「CSP の connect-src」は「起動したあとに外へ何かを送ることは一切ありません」と書いています
- 絵文字は見出しだけに使っています
- 教室での出来事を実体験としては書いていません
- 効果は言い切らず、「〜だと思います」「〜になればいいと思って作りました」で止めています
- 見出しは基本の6本に、📱 と ✨ のあいだへ2本だけ足しました。
  「🎲 いちばんおもしろいのは、渡すコマを自分が選ぶところ」と
  「🖥️ 電子黒板に映して、クラス全員で考える」です
- 本文はおよそ7,100字です
